# TURBO-GP, step by step

An interactive slide deck (a static website) explaining how TURBO-GP works:
the empirical 2-point-correlation kernel of Gomes et al. (2025) inside
[treegp](https://github.com/PFLeget/treegp), solved on a grid with the FFT
and conjugate gradient, as described in [RTN-129](https://rtn-129.lsst.io).

## Open it

- Online: https://pfleget.github.io/treegp/ (published from the `slides/`
  directory of the treegp repository by the GitHub Pages workflow
  `.github/workflows/pages.yaml` on every push to `master`; the repository
  owner has to enable Pages once, in Settings > Pages > Build and deployment >
  Source: "GitHub Actions").
- Locally: double-click `index.html` (everything is vendored in `js/lib/`, it
  works offline from `file://`), or serve the directory:

      python3 -m http.server 8000
      # then open http://localhost:8000/index.html

Arrow keys navigate; the down arrow opens the real-data companion of a
slide; `Esc` shows the overview. Green badges mark panels built from a real
LSSTCam visit processed by treegp, orange badges mark synthetic
toys computed live in the browser (`js/num.js`).

## Rebuild the real-data pieces

`data/visit.js` is generated by `make_data.py` from the real LSSTCam visit
`data/rubin_visit_2025052000348.npz` (float32: `u, v` in degrees, `du, dv,
du_err, dv_err` in mas, `visit`, `band`; 163 661 stars, 3.4 MB; the same file
is served at https://pfleget.github.io/treegp/data/rubin_visit_2025052000348.npz)
with treegp >= 1.5 and treecorr installed:

    python3 make_data.py                      # reads data/rubin_visit_2025052000348.npz
    python3 make_data.py --data visit.pkl     # or the original pickle
    python3 make_data.py --data visit.pkl --write-npz   # regenerate the npz

It runs the TURBO-GP solve on 10 000 training stars per component (seconds),
exports the intermediate products the slides show (including all training
stars, so that slides 7b and 10 can rebuild the whole solver grid in the
browser), and fits the L21 anisotropic von Kármán kernel for the comparison
slide (about 25 minutes per component because of the bootstrap). The L21
results are cached in `data/cache_l21.pkl`; delete that file to refit, or pass
`--no-l21` to skip the comparison.

## The worked example of the treegp documentation

`example_l21_turbogp.py` is the script behind the "worked example" section of
the treegp documentation (`docs/treegp_gp_interp.rst`): it runs L21 and
TURBO-GP on the same visit and the same 10 000 training stars, compares the
E/B-mode correlation functions of the validation stars and writes the figure
`docs/rubin_visit_l21_turbogp.png`:

    python3 example_l21_turbogp.py --out ../docs/rubin_visit_l21_turbogp.png
    python3 example_l21_turbogp.py --no-l21   # TURBO-GP only, about 10 s

## Layout

- `index.html`: the reveal.js deck (KaTeX equations numbered as in RTN-129).
- `js/demos.js`: one init function per slide (Plotly figures and controls).
- `js/num.js`: numerics (FFT, von Kármán kernel, bilinear spreading, padded
  convolution, conjugate gradient, ...). Toy grids must be powers of two.
- `js/lib/`: vendored reveal.js 5.1.0, plotly.js 2.35.3, KaTeX 0.16.11.
- `css/style.css`, `make_data.py`, `example_l21_turbogp.py`, `data/visit.js`
  (generated), `data/rubin_visit_2025052000348.npz` (the visit),
  `data/cache_l21.pkl` (L21 cache).
